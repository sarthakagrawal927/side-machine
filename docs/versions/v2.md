# v2.0.0 — Tailscale transport

v2 keeps the v1 command surface and changes the default transport to the
existing Tailscale node `fleet-mac`. This removes the same-Wi-Fi requirement
without exposing SSH publicly.

## Migration from v1

1. Install and sign in to Tailscale on the controller using the same tailnet.
2. Update the controller `side-chick` executable to v2 and confirm
   `side-chick version` prints `2.0.0`.
3. Run `side-chick alive` and `side-chick status` from a different network.
4. Keep LAN access available by setting `SIDE_CHICK_TRANSPORT=lan`.

## Authentication

Do not embed the worker password in `side-chick`: command lines, shell history,
process listings, and dotfiles are not appropriate password stores. The worker
already has Tailscale SSH enabled, so an authorized user in the same tailnet
can authenticate with tailnet identity. `side-chick setup-key` remains the
portable fallback and authorizes one dedicated SSH public key after a single
LAN password prompt.

## Overrides

| Variable | Purpose | Default |
| --- | --- | --- |
| `SIDE_CHICK_TRANSPORT` | Select `tailscale` or `lan` | `tailscale` |
| `SIDE_CHICK_TAILSCALE_TARGET` | Tailscale SSH destination | `assistant@fleet-mac` |
| `SIDE_CHICK_LAN_TARGET` | Bonjour/LAN SSH destination | `assistant@Assistants-MacBook-Pro.local` |
| `SIDE_CHICK_TARGET` | Override the selected destination | unset |
| `SIDE_CHICK_IDENTITY` | Dedicated fallback private-key path | `~/.ssh/id_ed25519_side_chick` |
| `SIDE_CHICK_TAILSCALE_SOCKET` | Use a nonstandard local daemon socket | unset |

No Tailscale auth keys, node keys, private keys, or tailnet policy files belong
in this repository.
